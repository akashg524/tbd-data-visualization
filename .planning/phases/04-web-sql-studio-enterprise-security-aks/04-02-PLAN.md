# Plan 04-02: Microsoft Entra ID SSO & Role-Based Access Control

<objective>
Implement enterprise-grade identity authentication and authorization using Microsoft Entra ID (Azure AD) JWT tokens, validate RS256 signatures via Azure discovery keys, enforce Role-Based Access Control (RBAC) across data querying and admin routes, and provide an automated dev bypass for local developer workflows.
</objective>

<threat_model>
### Trust Boundaries
- Untrusted Client Request -> FastAPI Auth Middleware
- Token Claims -> RBAC Role Enforcer

### STRIDE Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Spoofing / Unauthorized Access | EntraIDAuthenticator | mitigate | Cryptographically verify RS256 signature against official Microsoft JWKS keys (`https://login.microsoftonline.com/{tenant_id}/discovery/v2.0/keys`) and validate expiration (`exp`) and audience (`aud`) |
| T-04-05 | Elevation of Privilege | RBAC Enforcer | mitigate | Enforce role check on endpoint handlers via strict FastAPI dependencies (`require_roles`) |
| T-04-06 | Denial of Service / JWKS Flooding | PyJWKClient | mitigate | Cache JWKS signing keys locally to prevent outbound HTTP requests on every authenticated query |
</threat_model>

  <files>

  <action>
    Update backend/app/config.py:
    - Add authentication settings:
      - `auth_enabled: bool = False` (defaults to False in dev/testing, True in production).
      - `entra_tenant_id: str = ""` (Microsoft Entra ID Tenant ID).
      - `entra_client_id: str = ""` (Application Client ID / App URI).
      - `entra_jwks_cache_ttl: int = 86400` (JWKS key cache duration in seconds).

    Create backend/app/auth/entra.py:
    - Implement `EntraIDAuthenticator`:
      - Subclass or wrap FastAPI `HTTPBearer`.
      - In production (`auth_enabled=True`):
        - Initializes `PyJWKClient` for `https://login.microsoftonline.com/{tenant_id}/discovery/v2.0/keys`.
        - Extracts Bearer token from `Authorization` header.
        - Resolves signing key matching token's `kid` header.
        - Decodes and validates JWT claims:
          - `algorithms=["RS256"]`
          - `audience=settings.entra_client_id`
          - `issuer=f"https://login.microsoftonline.com/{settings.entra_tenant_id}/v2.0"`
        - Returns claims dictionary containing `sub`, `roles`, and `preferred_username`.
      - In dev/testing mode (`auth_enabled=False`):
        - Injects default developer identity:
          `{"sub": "dev-analyst@enterprise.com", "name": "Dev Analyst", "roles": ["FinancialAnalyst", "DataEngineer", "SecurityAdmin"]}`.

    Create backend/app/auth/rbac.py:
    - Define standard roles:
      - `Role.FINANCIAL_ANALYST = "FinancialAnalyst"` (Read/Execute/Export/Launchers)
      - `Role.DATA_ENGINEER = "DataEngineer"` (Catalog refresh, Dimension Cache admin)
      - `Role.SECURITY_ADMIN = "SecurityAdmin"` (Datasource configurations, secrets)
    - Implement `require_roles(*allowed_roles: str)` FastAPI dependency:
      - Validates that user claims contain at least one of the allowed roles.
      - Inspects both `roles` and `groups` claims.
      - Raises `HTTPException(403, detail="Insufficient role permissions")` on denial.

    Export in backend/app/auth/__init__.py.
  </action>
  <verify>
    Run python -c "from app.auth import EntraIDAuthenticator, require_roles; print('Auth initialized')" to verify syntax.
  </verify>
  <done>
    Entra ID token validator and RBAC role dependencies are ready for endpoint integration.
  </done>
