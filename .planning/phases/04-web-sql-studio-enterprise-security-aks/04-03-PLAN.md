# Plan 04-03: Multi-Stage Production Dockerfiles & AKS Helm Chart

<objective>
Deliver hardened multi-stage production Docker images and an enterprise-grade AKS Helm chart featuring high-speed local NVMe/SSD scratch volume mounts for DuckDB out-of-core spill, multi-protocol service definitions, and Azure VNet Peering blueprints for on-premises database connectivity.
</objective>

<threat_model>
### Trust Boundaries
- Internet / Corporate WAN -> AKS Ingress Controller (Ports 80/443)
- Power BI Desktop / BI Gateways -> AKS LoadBalancer Service (Port 5433)
- Analytical Clients / Notebooks -> AKS LoadBalancer Service (Port 5005)
- AKS Worker Nodes -> Azure VNet Peering / ExpressRoute -> On-Premises Databases

### STRIDE Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-07 | Elevation of Privilege | Docker Containers | mitigate | Run backend and frontend containers under non-root users (`appuser` with UID 10001, `nginx` with UID 101) with read-only root filesystems where possible |
| T-04-08 | Denial of Service / Disk Space Exhaustion | DuckDB Scratch Volume | mitigate | Configure `emptyDir.sizeLimit` on `/scratch` to prevent runaway joins from filling worker node root OS disks |
| T-04-09 | Information Disclosure | Kubernetes Secrets | mitigate | Reference secrets via Azure Key Vault CSI provider or Kubernetes secret references without plaintext committing |
</threat_model>

  <name>Create Production Multi-Stage Dockerfiles and Nginx Config</name>
  <files>
    Dockerfile.backend
    frontend/Dockerfile
    frontend/nginx.conf
  </files>
  <action>
    Update Dockerfile.backend:
    - Multi-stage build:
      - Stage 1 (builder): Python 3.13-slim, installs gcc, libpq-dev, builds python wheels.
      - Stage 2 (runtime): Clean Python 3.13-slim, creates non-root user `appuser` (UID 10001), copies wheels, installs dependencies, sets up `/scratch` directory owned by `appuser`.
      - Exposes ports `8000`, `5433`, `5005`.
      - Healthcheck hitting `/api/v1/health`.
      - Entrypoint running `uvicorn app.main:app --host 0.0.0.0 --port 8000`.

    Create frontend/nginx.conf:
    - SPA routing with `try_files $uri $uri/ /index.html`.
    - Reverse proxy for `/api/v1/` to backend service `http://data-hub-backend:8000`.
    - Gzip compression for JS, CSS, and SVG assets.
    - Security headers: `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`.

    Update frontend/Dockerfile:
    - Stage 1 (builder): `node:20-slim`, `npm ci`, `npm run build`.
    - Stage 2 (runtime): `nginx:alpine`, copies built assets from builder to `/usr/share/nginx/html`, copies `nginx.conf`, exposes port 80.
  </action>
  <verify>
    Verify Dockerfile syntax and check files exist.
  </verify>
  <done>
    Production-ready non-root Dockerfiles created for backend and frontend.
  </done>
</task>

<task type="auto">
  <name>Build AKS Helm Chart with Local NVMe Scratch Storage</name>
  <files>
    deploy/helm/data-hub/Chart.yaml
    deploy/helm/data-hub/values.yaml
    deploy/helm/data-hub/templates/deployment-backend.yaml
    deploy/helm/data-hub/templates/deployment-frontend.yaml

    deploy/helm/data-hub/templates/configmap.yaml
    deploy/helm/data-hub/templates/secrets.yaml
    deploy/vnet-peering-blueprint.md
  </files>
  <action>
    Create deploy/helm/data-hub/:
    - `Chart.yaml`: Helm chart metadata (name: `data-hub`, version: `1.0.0`).
    - `values.yaml`: Default production values for image repositories, replicas, resource requests/limits, scratch disk (`sizeLimit: 100Gi`), and security config.
    - `templates/deployment-backend.yaml`:
      - Deployment managing backend pods.
      - Mounts high-speed local NVMe/SSD `emptyDir` scratch volume at `/scratch`.
      - Sets environment variables: `DUCKDB_TEMP_DIRECTORY=/scratch`, `MAX_MEMORY=32GB`, `PORT=8000`, `PGWIRE_PORT=5433`, `FLIGHT_PORT=5005`.
      - Liveness and readiness HTTP probes on `/api/v1/health` and `/api/v1/ready`.
    - `templates/deployment-frontend.yaml`: Deployment managing Nginx frontend pods.
    - `templates/service.yaml`: Multi-port Kubernetes Service exposing:
      - `http`: 8000 (REST API / Web Studio)
      - `pgwire`: 5433 (PostgreSQL Wire Protocol for Power BI DirectQuery)
      - `flight`: 5005 (Apache Arrow Flight for batch imports)
    - `templates/ingress.yaml`: Ingress resource routing web traffic with TLS annotations.
    - `templates/configmap.yaml`: App settings, DuckDB memory settings, CORS origins.
    - `templates/secrets.yaml`: Secret template for Key Vault integration.

    Create deploy/vnet-peering-blueprint.md:
    - Complete architecture guide detailing:
      - AKS Virtual Network topology (`10.240.0.0/16`).
      - Azure ExpressRoute / Site-to-Site VPN Hub VNet peering (`10.0.0.0/8`).
      - Private DNS Zones and Private Endpoints for ADLS Gen2, Azure SQL, and Cosmos DB.
      - Network Security Group (NSG) egress rules allowing Oracle (1521) and SQL Server (1433).
  </action>
  <verify>
    Run tests in tests/test_helm_and_docker.py verifying manifests and configurations.
  </verify>
  <done>
    Helm chart and network blueprint fully parameterize production AKS deployment with NVMe scratch spilling and multi-protocol exposure.
  </done>
