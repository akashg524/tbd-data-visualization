# Plan 03-01: Two-Tier Dimension Cache, OData v4 Feeds & One-Click Launchers

<objective>
Build the second tier of the acceleration engine (DimensionCache) to eliminate network hops on slow reference tables during cross-source joins, and implement Denodo-style OData v4 feeds and one-click .pbids/.odc connection file generators for Excel and Power BI.
</objective>

<threat_model>
### Trust Boundaries
- Client / Power BI / Excel -> OData API Endpoint
- Client -> PBIDS / ODC Download Endpoint
- DimensionCache -> Remote Connectors

### STRIDE Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service / Memory Exhaustion | DimensionCache | mitigate | Cap maximum cached dimension size (e.g. 100,000 rows / 100MB) and reject fact tables |
| T-03-02 | Tampering / Parameter Injection | OData Parser | mitigate | Sanitize $filter and $select clauses using structured AST conversion |
| T-03-03 | Information Disclosure | PBIDS Generator | mitigate | Omit plain-text credentials from generated .pbids/.odc connection files; rely on server authentication |
</threat_model>

  <action>
    Create backend/app/api/odata.py:
    - GET /api/v1/odata/$metadata: Returns EDM XML schema definition generated from UnifiedCatalogRegistry.
    - GET /api/v1/odata: Returns service document listing available entity sets.
    - GET /api/v1/odata/{schema}/{table}: Accepts OData query parameters:
      - $filter: translates basic operators (eq, ne, gt, lt, ge, le, and, or) to SQL WHERE conditions.
      - $select: restricts projected columns.
      - $top, $skip: pagination.
      - $orderby: sorting.
      - Executes query via FederatedExecutor and returns standard OData v4 JSON envelope ({"@odata.context": "...", "value": [...]}).

    Register odata router in backend/app/api/__init__.py.
    Write tests in tests/test_odata_api.py verifying $metadata, entity sets, $filter, $select, and $top pagination.
  </action>
