# Plan 03-01: Two-Tier Dimension Cache, RESTful Views API & OData v4 Feeds

<objective>
Build the second tier of the acceleration engine (DimensionCache) to eliminate network hops on slow reference tables during cross-source joins, and implement Denodo-style RESTful Views API, OData v4 feeds, and one-click .pbids/.odc connection file generators for Excel and Power BI.
</objective>

<threat_model>
### Trust Boundaries
- Client / Web App / Microservice -> RESTful Views API Endpoint
- Client / Power BI / Excel -> OData API Endpoint
- Client -> PBIDS / ODC Download Endpoint
- DimensionCache -> Remote Connectors

### STRIDE Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service / Memory Exhaustion | DimensionCache | mitigate | Cap maximum cached dimension size (e.g. 100,000 rows / 100MB) and reject fact tables |
| T-03-02 | Tampering / Parameter Injection | REST Views & OData Parser | mitigate | Sanitize query parameters and $filter clauses using structured AST conversion |
| T-03-03 | Information Disclosure | PBIDS Generator | mitigate | Omit plain-text credentials from generated .pbids/.odc connection files; rely on server authentication |
</threat_model>

<task type="auto">
  <name>Implement RESTful Table Views API</name>
  <files>
    backend/app/api/views.py
    backend/app/api/__init__.py
    tests/test_views_api.py
  </files>
  <action>
    Create backend/app/api/views.py:
    - GET /api/v1/views/{schema}/{table}:
      - Query params:
        - fields: comma-separated list of column names (e.g. fields=trade_id,amount).
        - sort: column name to sort by, prefix with '-' for descending (e.g. sort=-amount).
        - limit: row limit (default 100, max 10000).
        - offset: row offset (default 0).
        - Dynamic filter parameters (e.g. amount__gt=1000, country=US, status=SETTLED).
      - Automatically synthesizes SQL query: SELECT {fields} FROM {schema}.{table} WHERE {filters} ORDER BY {sort} LIMIT {limit} OFFSET {offset}.
      - Executes query via FederatedExecutor.
      - Content negotiation:
        - Accept: application/json (default) -> JSON array with columns, rows, total_count, and execution metrics.
        - Accept: text/csv -> streamed CSV response.
    - GET /api/v1/views: Lists all available views in catalog with schemas and table paths.

    Register views router in backend/app/api/__init__.py.
    Write tests in tests/test_views_api.py verifying view listing, column projection, dynamic filtering, sorting, pagination, and CSV streaming.
  </action>
  <verify>
    Run pytest tests/test_views_api.py -v.
  </verify>
  <done>
    RESTful Views API serves filtered, paginated JSON and CSV data across virtual catalog tables.
  </done>
</task>
