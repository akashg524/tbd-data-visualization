# Plan 02-02: Federated Execution Engine, Out-of-Core Scratch Store & Result Cache

<objective>
Implement the asynchronous federated execution engine that coordinates parallel subquery fetching across remote data sources, enables DuckDB out-of-core spilling to expandable local SSD/NVMe scratch storage to prevent OOM errors, integrates a result cache for instant repeat queries, and streams results to the client.
</objective>

<threat_model>
### Trust Boundaries
- Client / Power BI -> API Query Endpoint
- FederatedExecutor -> In-Memory & Disk-Spilling DuckDB Engine
- FederatedExecutor -> ResultCache & Remote Connectors

### STRIDE Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Denial of Service / Memory Exhaustion | DuckDB Joiner | mitigate | Set DuckDB memory limits (max_memory) and enable automatic disk spilling to local scratch NVMe storage (temp_directory) |
| T-02-05 | Denial of Service / Hanging Queries | Subquery Dispatcher | mitigate | Enforce timeout (e.g. 60s) on parallel connector subquery executions via asyncio.wait_for |
| T-02-06 | Information Disclosure | Execution Metrics | mitigate | Sanitize execution plan and timing metrics before returning to API consumers |
</threat_model>

<task type="auto">
  <name>Implement FederatedExecutor with Out-of-Core Scratch Spilling</name>
  <files>backend/app/federation/executor.py</files>
  <action>
    Create backend/app/federation/executor.py:
    - Define ExecutionMetrics model (planning_ms: float, subquery_ms: dict[str, float], join_ms: float, total_ms: float, row_count: int, cache_hit: bool).
    - Implement FederatedExecutor:
      - __init__(catalog: UnifiedCatalogRegistry, cache: ResultCache | None = None, scratch_dir: str = "./scratch", default_timeout: float = 60.0).
      - async execute(sql: str, limit: int | None = None) -> tuple[pa.Table, ExecutionMetrics]:
        1. Check ResultCache: if cached, return immediately with cache_hit=True (<5ms).
        2. Parse and compile query using SQLParser and PushdownCompiler.
        3. If single-source: execute directly via connector.execute_query() and return.
        4. If multi-source:
           a. Concurrently fetch subqueries across connectors using asyncio.gather with timeout.
           b. Open isolated DuckDB connection configured with temp_directory pointing to scratch_dir and max_memory ceiling.
           c. Register each Arrow result table as view (__subq_{alias}) via conn.register().
           d. Execute rewritten root SQL.
           e. Convert result to pyarrow.Table.
           f. Store in ResultCache for future hits.
           g. Record detailed timing metrics.
  </action>
  <verify>
    Run pytest tests/test_federated_executor.py -k engine -v.
  </verify>
  <done>
    FederatedExecutor coordinates parallel subquery execution, enables out-of-core disk spilling to scratch store, and computes in-memory hash joins in DuckDB.
  </done>
</task>
