# Plan 02-02: Federated Execution Engine & In-Memory Hash Joiner

<objective>
Implement the asynchronous federated execution engine that coordinates parallel subquery fetching across remote data sources, registers Arrow tables into an in-memory DuckDB instance zero-copy, executes high-speed hash joins, and streams results to the client.
</objective>

<threat_model>
### Trust Boundaries
- Client / Power BI -> API Query Endpoint
- FederatedExecutor -> In-Memory DuckDB Engine
- FederatedExecutor -> Remote Connectors

### STRIDE Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Denial of Service / Memory Exhaustion | DuckDB Joiner | mitigate | Set DuckDB memory limits and enable automatic disk spilling to local scratch NVMe storage |
| T-02-05 | Denial of Service / Hanging Queries | Subquery Dispatcher | mitigate | Enforce timeout (e.g. 60s) on parallel connector subquery executions via asyncio.wait_for |
| T-02-06 | Information Disclosure | Execution Metrics | mitigate | Sanitize execution plan and timing metrics before returning to API consumers |
</threat_model>

<task type="auto">
  <name>Implement FederatedExecutor Engine</name>
  <files>backend/app/federation/executor.py</files>
  <action>
    Create backend/app/federation/executor.py:
    - Define ExecutionMetrics model (planning_ms: float, subquery_ms: dict[str, float], join_ms: float, total_ms: float, row_count: int).
    - Implement FederatedExecutor:
      - __init__(catalog: UnifiedCatalogRegistry, default_timeout: float = 60.0).
      - async execute(sql: str, limit: int | None = None) -> tuple[pa.Table, ExecutionMetrics]:
        1. Parse and compile query using SQLParser and PushdownCompiler.
        2. If single-source: execute directly via connector.execute_query() and return.
        3. If multi-source:
           a. Concurrently fetch subqueries across connectors using asyncio.gather with timeout.
           b. Open isolated in-memory DuckDB connection (with iceberg/parquet extensions loaded).
           c. Register each Arrow result table as view (__subq_{alias}) via conn.register().
           d. Execute rewritten root SQL.
           e. Convert result to pyarrow.Table.
           f. Record detailed timing metrics.
  </action>
  <verify>
    Run pytest tests/test_federated_executor.py -k engine -v.
  </verify>
  <done>
    FederatedExecutor coordinates parallel subquery execution, performs zero-copy Arrow registration, and computes in-memory hash joins in DuckDB.
  </done>
