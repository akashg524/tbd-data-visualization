The Strategic Opportunity Problem vs. Solution

Replacing High-Cost Virtualization with Modern Open Standards

✕ The Legacy Dilemma (Denodo / ETL Marts)
  • • Massive Licensing Toll: Commercial virtualization platforms (Denodo, Dremio) cost $150k–$500k+ annually in core licensing fees.
  • • ETL Duplication & Drift: Copying 100 TB of transactional trade and risk data creates stale pipelines and multi-hour data latency.
  • • Catalog Lock-In: Invasive schema modifications violate read-only upstream database constraints.
  • • Brittle Client Security: DAX-based RLS inside Power BI fails to protect direct exports or non-Power BI clients.
✓ The Built In-House Semantic Solution
  • • Zero Licensing Cost: Built entirely on open-source vector engines (DuckDB, PyArrow, FastAPI, SQLGlot, BuenaVista).
  • • Zero ETL / Zero Catalog Modification: Queries live data in place via 100% read-only connections (`ApplicationIntent=ReadOnly`).
  • • Universal Two-Gate Security: Dynamic SQL AST rewrite injects row-level security before pushdown planning, uniform across all protocols.
  • • Direct Power BI Integration: Native PostgreSQL wire protocol listener allows immediate DirectQuery with zero custom desktop drivers.
Key Outcome: High-throughput federated analytics across 10 TB – 100 TB at sub-second response times. 100% Read-Only Upstream • Zero Impact

Enterprise Data Governance Fine-Grained Security

The Two-Gate Declarative Policy & AST Rewrite Engine

Gate 1: Coarse-Grained Table RBAC Pre-Planning

Validates that the caller's Entra ID token possesses role membership for every physical table referenced in the incoming SQL query.

Table: corporate.mna_deals
Required Roles: ['MNA_Auditor', 'SecurityAdmin']
Unauthorized access throws 403 Forbidden immediately before any data scan.
Gate 2: Fine-Grained Dynamic RLS AST Injection

Rewrites the AST to inject row-level filter predicates matching user claims into the query's enclosing WHERE clause.

Trading Desk: desk_code = 'FX' (DIRECT)
Regions: region_id IN (1, 2) (TRANSLATION)
Zero Claims: Strictly fails closed with 1 = 0.
Zero Catalog Drift: Iceberg catalog remains completely untouched.
Strict Hierarchical Priority: Specific desk claims take precedence over broad regions.
Auditor Exemption: Compliance officers bypass RLS for complete audits.
SQLGlot AST Rewriter Live Query Transformation

Transparent AST Filter Injection & Cache Isolation

1. Incoming Power BI Query:
SELECT t.trade_id, c.name, t.amount
FROM adls_lake.equity.trades t
JOIN oracle_dw.risk.counterparties c
  ON t.counterparty_id = c.id
WHERE t.amount > 10000
Analyst submits clean SQL without manual filter overhead.
2. Secured AST Execution Plan:
SELECT t.trade_id, c.name, t.amount
FROM adls_lake.equity.trades t
JOIN oracle_dw.risk.counterparties c
  ON t.counterparty_id = c.id
WHERE t.amount > 10000
  AND t.desk_code = 'FX'
  AND t.region_id IN (1, 2)
  AND c.region_id IN (1, 2)
Table aliases qualified; multiple claims combined with AND.
Fingerprint-Isolated Result Caching: Cache key = hash(SQL + sec_fingerprint)
Guarantees Zero Cross-Desk Data Leaks
Speed Layer Engine Vectorized Execution

Native Predicate Pushdown & In-Memory Hash Joins

1. Native Pushdown Compiler

Decomposes cross-source queries. Pushes WHERE filters and column projections directly to upstream databases in their native dialect.

Oracle receives: WHERE id IN (...) AND region_id IN (1, 2)
Zero unnecessary columns transferred across WAN.
2. Parallel PyArrow Streaming

Simultaneously reads ADLS Iceberg Parquet files and fetches relational cursor batches into zero-copy PyArrow columnar tables.

Batch transport over HTTP/2 and TCP.
Direct memory mapping with zero Python GIL stalls.
3. Vectorized DuckDB Joiner

Executes cross-source hash joins across millions of rows at C++ vectorized speeds.

Out-of-core spill to NVMe SSD at /scratch prevents OOM errors on multi-GB joins.
Benchmarked throughput: 10M rows joined and returned in < 1.8 seconds. Linear Scaling with Thread Count
